# axum-generated-server

Unlike [`axum-models-only`](../axum-models-only) — where you write the axum server by hand against generated *models* — this example generates the **server** too. `openapi-modelgen` emits an `Api` trait (one method per operation) plus an axum adapter, so forgetting to implement a route becomes a **compile error**.

## How it works

With `server`/`axum-server` generation on, `notes-openapi` contains a `src/server.rs` with:

- A framework-agnostic `Api` trait — one method per operation, no default bodies. `State`, `Error`, and a general `Ctx` extractor are associated types **you** choose; modelgen never dictates them.
- A `router::<A>() -> axum::Router<A::State>` (behind the `server-axum` feature) that wires every operation, extracts + validates inputs, and calls your trait method. It returns the router **without** applying state, so you merge any manual routes and call `.with_state(...)` last.

You implement the trait once (`notes-server/src/api.rs`). Because the methods have no defaults, **adding an operation to `openapi.yaml` and regenerating makes the app stop compiling until you handle it** — `error[E0046]: not all trait items implemented`. That is the safety net.

### Spec-driven authentication

`POST /notes` declares `security: [bearerAuth]` in the spec. modelgen reacts to that: it emits a `type Auth` slot and injects an `auth: Self::Auth` argument **into `create_note` only** — the public `list_notes`/`get_note` don't get it. You satisfy `Auth` with an `AuthUser` extractor (`notes-server/src/extract.rs`) that checks the `Authorization: Bearer` header and returns 401 before the handler runs. A spec with no `security` anywhere emits no auth machinery at all.

### Manual opt-out

Some handlers need bespoke wiring the trait can't express. `openapi-modelgen.yaml` marks `deleteNote` as `manual`, so it is dropped from the trait entirely (and listed in a doc comment in `server.rs`). You wire it by hand and merge it into the generated router — see `main.rs`. Because `router` returns `Router<A::State>` without applying state, your manual handler can use the `State` extractor just like the generated ones.

```yaml
# openapi-modelgen.yaml
generate:
  model: true
  server: true
  axum-server: true
server-style: strict
operations:
  deleteNote:
    server-style: manual
```

## Structure

```
.
├── Cargo.toml                  # workspace root
├── openapi.yaml                # API spec (source of truth)
├── openapi-modelgen.yaml       # generation config (targets + manual opt-out)
├── notes-server/               # your application
│   └── src/
│       ├── state.rs            # AppState (your `type State`)
│       ├── error.rs            # AppError: IntoResponse + From<ValidationError>
│       ├── extract.rs          # AuthUser: the FromRequestParts guard (your `type Auth`)
│       ├── api.rs              # impl Api for NotesApi (list/create/get — compile-enforced)
│       └── main.rs             # router::<NotesApi>() + manual DELETE + /healthz + with_state
└── notes-openapi/              # generated by openapi-modelgen
    └── src/
        ├── model.rs            # Note, NewNote, ListNotesQuery
        ├── validation.rs       # Validation trait impls
        └── server.rs           # the Api trait + axum `router`
```

## Regenerating the crate

From the openapi-modelgen project root:

```sh
cargo run -- \
  --input examples/axum-generated-server/openapi.yaml \
  --output-dir examples/axum-generated-server \
  --crate-name notes-openapi \
  --workspace \
  --config examples/axum-generated-server/openapi-modelgen.yaml
```

## Running

```sh
cd examples/axum-generated-server
cargo run -p notes-server
# listening on http://127.0.0.1:3000
```

In another terminal:

```sh
# Public: list (filter by tag, limit is validated 1..=100)
curl 'http://127.0.0.1:3000/notes?tag=errand&limit=5'

# Public: get one
curl http://127.0.0.1:3000/notes/1

# Secured: create WITHOUT a token -> 401 (AuthUser guard rejects before the handler)
curl -i -X POST http://127.0.0.1:3000/notes \
  -H 'Content-Type: application/json' \
  -d '{"text": "Water the plants"}'

# Secured: create WITH a bearer token
curl -X POST http://127.0.0.1:3000/notes \
  -H 'Authorization: Bearer letmein' \
  -H 'Content-Type: application/json' \
  -d '{"text": "Water the plants", "tag": "home"}'

# Validation error (empty text) -> 422 with structured JSON
curl -i -X POST http://127.0.0.1:3000/notes \
  -H 'Authorization: Bearer letmein' \
  -H 'Content-Type: application/json' \
  -d '{"text": ""}'

# Manual route (hand-wired, merged into the generated router) -> 204
curl -i -X DELETE http://127.0.0.1:3000/notes/1

# Non-spec route
curl http://127.0.0.1:3000/healthz
```

## Limitations shown here

- **Path parameters are always `String`** — the spec type isn't mapped to a Rust type yet.
- **Only `$ref` (and arrays of `$ref`) bodies/responses are typed** — other inline schemas degrade to `()`.
